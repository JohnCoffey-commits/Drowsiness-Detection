# Evidence-Fused Driver Drowsiness Warning-Candidate System

Final Technical Report | Drowsiness Detection Project

## Claim Boundary

This report describes specialist-module metrics and rule-based warning-candidate behavior. It does not claim final system-level driver drowsiness accuracy, clinical validation, real-road validation, or deployment readiness.

## Abstract

This project implements a modular driver drowsiness warning-candidate prototype. Instead of training one end-to-end drowsy/not-drowsy classifier, it separates visible facial evidence into two specialist channels: a mouth/yawn model trained on YawDD/YawDD+ Dash evidence and an eye open/closed model trained on MRL Eye. The model outputs, `p_yawn` and `p_eye_closed`, are processed by signal-quality checks, temporal rules, and a fusion layer to produce review-oriented warning-candidate states.

The selected mouth/yawn specialist is ResNet18, with 99.37% test accuracy and 97.18% yawn F1 in the completed Stage 7 run. The selected eye specialist is MobileNetV2, with 98.63% test accuracy and 98.63% macro F1 in the Stage 9/9B evaluation. Later stages focus on runtime evidence alignment, quality checks, and rule-based fusion rather than new model training.

## 1. Architecture Overview

The system can be understood as four layers:

| Layer | Role |
| --- | --- |
| Data layer | Reconstructs and validates YawDD/YawDD+ Dash mouth evidence and MRL Eye evidence. |
| Training layer | Compares ResNet18, MobileNetV2, and EfficientNet-B0 baselines for each specialist task. |
| Runtime layer | Extracts ROIs from full-face video frames and computes `p_yawn` and `p_eye_closed`. |
| Application layer | Exposes uploaded-video analysis, realtime monitoring UI, history, insights, and local archive summaries. |

The backend entry point is `src/backend/app.py`. Uploaded-video analysis is handled by `src/runtime/system_video_upload_pipeline.py`. Realtime evidence is generated by `src/runtime/realtime_frame_inference.py`, and session-local temporal state is maintained in `src/runtime/realtime_temporal_state.py`.

## 2. Data Processing

The YawDD/YawDD+ Dash mouth branch was reconstructed into 64,378 labeled frames across 29 subjects. The class distribution contains 57,347 `no_yawn` frames and 7,031 `yawn` frames. Mouth ROI generation produced 64,202 trainable crops with a 99.73% success rate.

The mouth/yawn split is subject-level rather than frame-random:

| Split | Subjects | Images | no_yawn | yawn | Yawn rate |
| --- | ---: | ---: | ---: | ---: | ---: |
| Train | 20 | 44,156 | 39,345 | 4,811 | 10.90% |
| Validation | 4 | 8,892 | 7,902 | 990 | 11.13% |
| Test | 5 | 11,154 | 9,924 | 1,230 | 11.03% |

The MRL Eye branch contains 84,898 eye images across 37 subjects, with 41,946 closed-eye images and 42,952 open-eye images. The subject-level split contains 58,982 training images, 13,029 validation images, and 12,887 test images.

## 4. Runtime Fusion Logic

The runtime system does not treat single-frame probabilities as final drowsiness labels. It combines evidence over time and checks signal quality before producing warning-candidate states.

The eye path computes a rolling PERCLOS-like binary mean and applies quality gates. If face visibility is poor, the system marks the evidence as unreliable instead of interpreting it as eye closure. The mouth path computes `p_yawn = softmax(logits)[1]` and keeps recent-yawn context for a short temporal window.

The fusion layer uses these states:

| State | Meaning |
| --- | --- |
| `normal` | No active warning-candidate evidence. |
| `eye_warning_candidate` | Eye evidence suggests possible sustained eye closure or reduced eye openness. |
| `mouth_warning_candidate` | Mouth evidence suggests yawn-related behavior or recent-yawn context. |
| `high_confidence_drowsiness_candidate` | Eye warning evidence and recent-yawn evidence overlap. |
| `signal_unreliable` | Face or ROI quality is too weak for reliable interpretation. |

These states are evidence categories for review, not ground-truth fatigue labels.

## 5. Controlled Runtime Validation

Stage 15 synchronizes real eye timelines and real mouth/yawn timelines for four controlled videos and applies the fusion rule.

| Video | Normal | Eye | Mouth | High Confidence | Signal Unreliable |
| --- | ---: | ---: | ---: | ---: | ---: |
| A_normal_open_baseline | 70 | 0 | 0 | 0 | 0 |
| B_realistic_drowsy_simulation | 49 | 18 | 30 | 6 | 0 |
| C_mild_head_motion | 76 | 7 | 0 | 0 | 12 |
| D_controlled_long_open_closed | 54 | 65 | 0 | 0 | 0 |

The normal baseline stays normal. The drowsy simulation produces mouth warnings, eye warnings, and several high-confidence candidates where evidence overlaps. The mild head-motion case produces signal-unreliable states, which is expected when face/ROI quality is weak.

## 6. Application Surface

The repository includes a FastAPI backend and a Next.js frontend on the UI branch. The uploaded-video workflow packages sampled frames, warning-candidate intervals, plots, keyframes, and summary values into an API response. The realtime workflow samples webcam frames and maintains session-local warning-candidate state.

The frontend displays backend evidence and user-facing summaries. It does not retrain models and does not replace backend fusion decisions.

## 7. Limitations

The main limitation is generalization. The mouth model is trained on reconstructed Dash mouth crops, the eye model is trained on MRL Eye images, and runtime inference relies on MediaPipe-derived ROIs. These domains are related but not identical.

The current validation shows plausible behavior in a small controlled setting, but it does not establish road-level performance, driver-level fatigue ground truth, or robustness across camera placement, lighting, glasses, occlusion, skin tone, and vehicle conditions.

A deployment-grade extension would need synchronized mouth-eye video data, temporal ground-truth annotation, subject/camera/lighting-stratified evaluation, and potentially a learned temporal fusion model after enough annotated data are available.
